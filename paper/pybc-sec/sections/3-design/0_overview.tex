
\section{Study Goals and Research Questions}\label{sec:study}

This study asks whether Python bytecode artifacts create a meaningful security visibility and robustness gap beyond source-level analysis.  The study is motivated by three observations from Section~\ref{sec:background}: Python bytecode is executable, bytecode can appear without trustworthy source correspondence, and current security workflows often assume source is the primary analysis object.  Our goal is not to argue that arbitrary bytecode should be trusted.  Instead, we measure where bytecode appears, whether it is visible from source, whether existing tools recover it, and how runtime findings should be interpreted.

\subsection{Study Goal and Research Questions}\label{sec:study:goals-rqs}

\noindent\textbf{Study goal.}
This work asks whether Python bytecode artifacts create a meaningful security visibility and robustness gap beyond source-level analysis.

\noindent\textbf{To achieve this goal, we answer the following connected questions.}
We structure the study as a causal chain: establish bytecode presence (exposure), test whether source-level views match executable bytecode (visibility), measure whether tools can recover what is missing (coverage), and characterize runtime behaviors and their source-reproducibility (robustness).

\noindent\textbf{Goals.}
We define four study goals.

\noindent\textbf{G1: Measure bytecode exposure.}
Determine whether bytecode artifacts are common enough in realistic software distributions to matter for package security workflows.

\noindent\textbf{G2: Measure source visibility.}
Determine whether bytecode artifacts have corresponding source and whether the available source matches the bytecode that can be loaded or executed.

\noindent\textbf{G3: Measure tool coverage.}
Evaluate whether recovery tools produce source that parses, recompiles, and preserves bytecode or behavior.

\noindent\textbf{G4: Interpret runtime robustness.}
Study CPython behavior on unusual or mutated bytecode inputs and determine which abnormal outcomes are reproducible from ordinary Python source.

\noindent\textbf{Research questions.}
We organize the empirical study around five research questions.

\begin{description}[style=unboxed,leftmargin=0cm]
\denseitems
\item[\textbf{RQ1 (G1/G2):}] How prevalent and transparent are bytecode artifacts in Python distributions?
\item[\textbf{RQ2 (G3):}] \emph{How well do existing tools recover or analyze Python bytecode artifacts?}
\item[\textbf{RQ2 (G3):}] \emph{How effectively do existing tools decompile and inspect Python bytecode artifacts?}
\item[\textbf{RQ4 (G4):}] \emph{What bytecode behaviors cannot be expressed or reproduced through ordinary Python source?}
\end{description}

Section~\ref{sec:method} describes the methodology used to answer each question, and Section~\ref{sec:results} reports results using the same RQ structure.

Packaged bytecode exists in real Python distributions. Existing tools may not fully analyze it. CPython can exhibit unusual behavior on crafted bytecode. 
Some of these behaviors are not reproducible from ordinary source, so bytecode deserves direct security study.
