\begin{abstract}
Python security analysis is largely source-centric: package scanners, dependency analyzers, malware detectors, and program-analysis pipelines typically inspect Python source files, metadata, installation scripts, and dependency relations.  However, CPython executes compiled code objects, routinely materializes bytecode as \texttt{.pyc} files, and can load bytecode through source-less modules, cached imports, bundled applications, custom loaders, and marshalled code objects.  This creates a practical visibility gap: behavior may be present in executable bytecode even when corresponding source is missing, stale, mismatched, or difficult to recover.

This paper presents an empirical study of Python bytecode as a first-class security artifact.  We study how bytecode appears in PyPI distributions, how transparent those artifacts are to source-level inspection, how practically analyzable they are with selected tools, and how CPython behaves when processing malformed or adversarial bytecode inputs.  Our methodology combines package-scale artifact collection, bytecode/source inventory, version-aware tool analysis, CPython bytecode fuzzing, and tool-bounded source reproduction for abnormal behaviors.  The study is designed to separate ecosystem visibility risks from interpreter robustness findings and to distinguish source reproductions produced by selected tools from bytecode-level findings that those tools do not reproduce.

Our results show that Python bytecode deserves explicit treatment in package security workflows.  Bytecode artifacts can occur in package distributions, selected tools require version-aware environments to analyze them reliably, and bytecode-level testing can expose runtime robustness findings that require careful source-reproduction analysis.  These findings motivate bytecode-aware package scanning, explicit reporting of tool failures, more robust bytecode validation boundaries, and security tooling that treats compiled Python artifacts as analyzable inputs rather than disposable caches.

\end{abstract}
