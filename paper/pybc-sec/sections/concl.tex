\section{Conclusion}\label{sec:conclude}

Python bytecode is commonly treated as an internal cache, but it is also an executable artifact that can appear in package distributions and bytecode-loading workflows.  This paper presented {\tech}, an empirical methodology for measuring bytecode prevalence and transparency, practical analyzability, CPython robustness under bytecode fuzzing, and tool-bounded source reproduction.  The study shows why Python package security should not stop at source files: bytecode can fall outside source inventories, selected tools may require version-aware environments to analyze it, and malformed bytecode can exercise runtime behavior outside ordinary source-level workflows.  Bytecode-aware analysis provides a practical path toward more complete package scanning, clearer robustness triage, and stronger security tooling for the Python ecosystem.
